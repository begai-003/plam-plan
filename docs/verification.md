# 検証記録

検証日：2026年10月10日（日本時間）。Linux、Node.js 24.19.0、Java 21、Chromium 151。画像機能を廃止した版を、FirebaseのdemoプロジェクトとAuth／Firestore Emulatorで検証しています。Storage Emulator・バケット・Storage設定は使用しません。

|`npm run test:rules`|9件成功・失敗／スキップなし|

## 確認した機能

- キット登録、カード／リスト一覧、詳細、編集、削除は画像なしで動作。画像アップロード入力・画像タグは存在しません。
- ランナー・成形色、複数グループ割り当て、塗装工程・順序、混色70/30と不正な70/40の拒否、工程前のマスキング、番号未指定表示は維持しています。
- 塗料台帳の瓶ごとの残量、希釈済み本数、検索・絞り込み、論理削除・復元は維持しています。
- Auth Emulatorの公式Google資格情報APIで本人認証・別UID拒否・ログアウト・詳細ルートへの復帰を確認しています。
- ブラウザ2画面でrevision競合を発生させて上書きを拒否し、入力を保持。オフライン時の保存禁止、未保存入力の確認、Escapeでのモーダル終了とフォーカス復帰、360px幅の表示を確認しています。
- 旧imagePath付きキットをブラウザで閲覧・編集し、保存後にフィールドが除去されることを確認。Firestore Rulesも旧データの読み込み・フィールド除去を許可し、新規画像パスの登録・変更を拒否します。
- キット削除はFirestoreだけで実行します。旧imagePath付きのdeletingキット、削除中断後の再試行、古いrevisionの拒否、塗料台帳の保持をサービス契約テストで確認しています。
- 未認証・別UIDのFirestore操作、許可外フィールド・不正な型・createdAt変更・revision飛ばしをRulesテストで拒否しています。

## 未検証の範囲

本番Firebaseへの接続・Rules配備、実際のGoogleアカウントのポップアップ認証、公開ドメイン設定、GitHub Pages公開、Windows／macOS／iOS／AndroidやEdge／Firefox／Safariの実機検証は未実施です。Googleポップアップに関しては、以前の利用者の指定どおり、このクラウドのChromium証明書ストアを変更せず、公式Auth Emulatorの資格情報APIで検証しています。TLS検証は無効化していません。

Rulesの埋め込み配列の詳細な業務整合性はクライアントで検証します。本人以外のデータアクセスはRulesで拒否します。既存Storage上の画像にはアクセスも自動削除もしません。バックアップは設計どおり初期版の範囲に含めません。
